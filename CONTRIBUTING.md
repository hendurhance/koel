# Contributing to Koel

Thanks for taking the time to contribute.

## Development setup

### Option 1: Docker (recommended)

```bash
cp .env.example .env
docker compose up -d
docker compose exec api uv run alembic upgrade head
docker compose exec api uv run koel db seed
```

### Option 2: Local (no Docker)

Requires Python 3.12+, Postgres 14+, and Redis 7+.

```bash
./scripts/setup-local.sh
cp .env.example .env
uv run alembic upgrade head
uv run koel db seed
make dev
```

For full operational details, see [`docs/operations.md`](docs/operations.md).

## Project structure

- `koel/` — FastAPI app, jobs, domain logic, and CLI.
- `tests/` — unit, integration, and load tests.
- `frontend/` — Nuxt dashboard.
- `alembic/` — database migrations.
- `docs/` — architecture and operator docs.

## Code quality and tests

Run these before opening a PR:

```bash
make lint
make typecheck
make test-unit
```

Integration tests (requires live Postgres + Redis):

```bash
make test-integration
```

Frontend checks (from `frontend/`):

```bash
npm install
npm run typecheck
npm run build
```

## Migrations

If you change database models, include an Alembic migration.

```bash
uv run alembic revision --autogenerate -m "describe change"
uv run alembic upgrade head
```

Review autogenerated migrations carefully before committing.

## Pull requests

1. Keep changes focused and scoped to one concern.
2. Include tests for behavior changes.
3. Update docs when behavior, API, or operations change.
4. Ensure lint/typecheck/tests pass locally.
5. Write a clear PR description with context and verification steps.

## Security

Please do not open public issues for security vulnerabilities. Report them privately to the maintainers.
